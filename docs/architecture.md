# 架构设计

## 目标

第一阶段只建设 `market-data`，把“行情获取、落库、查询、页面展示”做稳定。

原则：

1. 东方财富只在本地 `market-data` 服务中访问。
2. DuckDB 只由 `market-data` 直接读写。
3. Web 页面和 AI 全部通过 REST API 查询。
4. 后续新增 Tushare、券商行情时，不改变上层接口。
5. 数据服务只负责客观行情与指标，不负责自动下单。

## 总体结构

```text
东方财富
   │
   ├─ eastmoney-data-sdk
   └─ 东财公开 HTTP 接口
   │
   ▼
market-data
   │
   ├─ 全市场分页同步
   ├─ 日 K / 分钟 K / 分时
   ├─ 指数 / 行业 / 概念板块
   ├─ 全市场技术指标
   ├─ 定时任务
   └─ market.duckdb
   │
   ▼
stock-select
   │
   ├─ 硬过滤 / 趋势过滤
   ├─ 形态识别 / 技术评分
   ├─ Top10 / 重点3只
   ├─ 次日交易计划
   ├─ 候选表现复盘
   ├─ 历史参数回测
   └─ select.duckdb
   │
   ▼
trade-manager
   │
   ├─ 明日重点计划同步
   ├─ 盘中1分钟监控
   ├─ 手工确认买入/卖出
   ├─ 已有持仓管理
   ├─ T+1约束
   ├─ 止损 / 止盈 / 移动止盈 / 时间退出
   └─ trade.duckdb
   │
   ├───────────────┐
   ▼               ▼
Web 管理页          AI 查询接口
```

## 模块

### services/market-data

后端数据服务。

职责：

- 获取全 A 股基础行情。
- 获取单股日 K、分钟 K、分时。
- 保存 DuckDB。
- 工作日收盘后自动增量同步。
- 提供历史日 K 初始化任务。
- 提供指数、行业、概念板块接口。
- 提供 AI 聚合接口。

### services/stock-select

收盘后选股服务。

职责：

- 只通过 market-data API 获取行情，不直接读取 market.duckdb。
- 默认排除北交所、科创板、ST。
- 只做 MA5/MA10/MA20 多头趋势。
- 识别缩量回踩、放量突破、强势后首次回踩、趋势延续。
- 保存 Top10 候选和重点3只。
- 为候选生成次日买入区、止损、止盈、移动止盈和时间止损计划。
- 默认工作日16:40自动执行。
- 选股历史独立保存在 select.duckdb。
- 每天自动复盘过去候选的次日表现和计划执行结果。
- 支持历史交易日重放，比较止损、目标、移动止盈和持有期参数。
- 回测建议只展示，不自动修改实盘参数。

### services/trade-manager

盘中执行与持仓服务。

职责：

- 通过 stock-select API 读取重点候选，不直接读取 select.duckdb。
- 通过 market-data API 读取实时行情和当日分时，不直接访问东方财富。
- 默认只监控重点3只，配置可调整到 Top10。
- 盘中每分钟更新一次执行状态。
- 买入和卖出必须由用户手工确认，不自动下单。
- 支持录入系统启用前已经持有的股票。
- 执行 A 股 T+1 约束：确认买入当天不可确认卖出。
- 节假日/停牌时用分时日期校验，不使用陈旧行情推进状态。
- 保存状态变化日志和已结束交易。
- 数据独立保存在 trade.duckdb。

### apps/web

本地管理页面。

页面：

- 市场总览
- 股票查询
- 板块对比
- 每日选股
- 策略复盘
- 数据同步

## DuckDB 表

### stock

股票基础信息。

### daily_price

每个交易日的股票行情和基础估值字段：

- 开盘、收盘、最高、最低、昨收
- 成交量、成交额
- 涨跌幅、振幅、换手率、量比
- PE、PB
- 总市值、流通市值

### minute_price

只保存用户查询、候选股或持仓的分钟数据。

不保存 5000 多只股票的全市场每一分钟，避免无意义的数据膨胀。

### sector

行业和概念板块实时排名。

### market_index

上证、深证、创业板、科创50、沪深300。

### sync_job

记录同步任务状态与进度。

### select_review

保存历史候选的次日行情、是否成交、最大浮盈/浮亏、退出原因和实际近似收益。

### backtest_run / backtest_parameter

保存历史回测批次、默认参数表现和排名靠前的参数组合。

### trade_plan

保存选股计划、已有持仓、当前执行状态、实际确认成交价格、移动止盈价格和最终退出结果。

### trade_event

保存每次状态变化，例如进入买入区、移动止盈启动、触发止损、T+1锁定、确认卖出等。

## 同步策略

### 每日增量

东财 `clist` 一次可以返回多只股票。

因此收盘后同步全市场时：

```text
约 5000 只股票
   ↓
每页 500 只
   ↓
约 10～12 次请求
   ↓
写入 daily_price
```

不需要逐只请求 5000 次。

### 历史初始化

第一次需要均线和趋势计算时，对每只股票逐个拉取最近 120～250 个交易日日 K。

这是一次性重任务，所以：

- 手动启动。
- 顺序执行。
- 每 20 只更新一次进度。
- 单只失败不终止全任务。

### 分钟数据

只在以下场景获取：

- 用户打开个股页面。
- AI 查询个股。
- 未来候选池监控。
- 当前持仓监控。

## 服务边界

```text
market-data   = 只负责“数据是什么”
stock-select  = 只负责“哪些股票符合策略、策略历史表现如何”
trade-manager = 只负责“今天该等待、可买、持有还是可卖”
Web           = 只负责展示和手工确认
AI            = 读取结构化结果，做解释、比较和二次判断
```

后续即使更换 Tushare、券商行情或增加其他策略，也不需要改变页面与 AI 的调用方式。

## AI 接口

### GET /api/v1/ai/market

一次返回：

- 主要指数
- 上涨/下跌家数
- 涨跌幅超过 3% 的家数
- 总成交额
- 涨幅前十
- 成交额前十
- 行业前十/后十
- 概念前十/后十

### GET /api/v1/ai/stock/:code

一次返回：

- 股票基础信息
- 实时行情
- 最近 120 日日 K
- 最近 1 分钟数据
- 当日分时
- MA5/MA10/MA20
- 5 日/20 日涨幅
- 20 日高点
- 相对 5 日成交量
- 距 MA5 偏离

stock-select 直接消费这些数据。

### GET /api/v1/trading/ai

一次返回：

- 当前重点计划和已有持仓
- 可买、可卖、T+1锁定等执行状态
- 当前止损和移动保护价
- 最近状态变化
- 选股、复盘和回测上下文

### GET /api/v1/select/ai

一次返回：

- 当前市场背景
- 最新选股批次
- 重点3只
- Top10候选
- 每只候选的次日执行计划
- 当前固定交易纪律
- 策略复盘胜率、盈亏比等统计
- 最近一次历史参数回测结果

## 后续阶段

下一阶段建议新增：

- 可选的券商只读持仓同步
- 历史1分钟数据精确回测
- 通知推送（企业微信/Telegram/邮件等）
- 不同策略版本对比
- Tushare 备用数据源
- 外网只读 API Key
