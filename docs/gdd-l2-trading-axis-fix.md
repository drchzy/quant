# GDD 实时盘口与分时全时段修复

## 修复说明

- **L2十档不显示**：此前Web只订阅WS type 1(快照)、type 2(逐笔)，未向GDD发送 `type=4` 盘口订阅。本版同时订阅1、2、4；允许type4关联250快照且保留盘口缓存，取消时同步退订。
- **右侧显示**：按真实GDD返回的 buyPrice0..9、buyVolume0..9、sellPrice0..9、sellVolume0..9（同时兼容对应数组字段）展示卖10～卖1、买1～买10；若只收到五档或者服务端未授权十档，不能声称已有L2数据。
- **诊断**：工作台下方「实时行情诊断」展示WS连接、当前订阅类型、最后ReqType、250/251/252消息计数、上游字段名、盘口有效档数、断线错误。只展示字段名，不展示账号或sessionCode。
- **固定分时时间轴**：即使只返回上午几分钟，横轴也始终延伸到15:00；09:15～09:25竞价、09:30～11:30、13:00～15:00三段独立渲染。竞价间隔与午休不画假连线，也不填充缺失数据。
- **竞价请求**：分时请求尝试 `timevalue0=75`（09:15），`timevalue1=420`（15:00）。如GDD后端不支持竞价扩展请求，自动退回原本验证通过的 `timevalue0=90` 并让竞价点位显示空白。数据不作推断。
- **股票名称和昨收/今开/最高/最低**：在切换股票时新增一次性的 `/api/v1/gdd/terminal/profile/:code` 查询。优先本地stock数据和真实WS，缺失时依据GDD历史日K和已启用的新浪/腾讯等quote源补充。WS轮询仍只读缓存，不会每2秒拉取外部HTTP。
- **数据来源**：顶部行情显示 WS / GDD历史日K / Quant缓存 / 其它行情来源，不把旧收盘价伪装为实时价。

## 调试步骤

1. 使用新版本镜像、在 `web/.env` 保留 Web/GDD 账号密码和 MCP Token，重新创建容器。
2. 登录Web并在「数据源管理」启用GDD；进入「GDD行情工作台 → 专业行情」，选择六位股票代码。
3. 展开「实时行情诊断」：订阅类型应包括 **1,2,4**。若连接正常却未收到250/251/252推送，可能是非交易时段或GDD服务器未授权；若250消息已到但买卖档位仍为空，检查“快照字段/盘口字段”是否与文档命名一致。
4. 在交易时段测试日K、分时与右侧盘口；如果原始GDD确实未提供10档，则不能通过页面代码凭空生成L2数据。

## 验证边界

CI使用模拟WS及固定时间轴样本，证明协议消息处理和UI构建可用；**不等于真实GDD已推送十档L2**。市场交易所午休没有新盘口消息属于正常情况。上游GDD HTTP与WS是明文，建议可信网络。
